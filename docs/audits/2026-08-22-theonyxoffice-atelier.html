The verdict

The site is well engineered where it counts: no console errors, no runtime exceptions, no failed requests, clean HTTPS with HSTS, immutable caching plus HTTP Range on media, gzipped JS, code splitting, zero layout shift, a single H1, and no horizontal overflow at any width. The craft in the motion and glass system is real.

Two things hold the score down: the exact URL being shared, /#atelier, does not actually land on the Atelier section, and the page ships roughly 49 MB of media with content images as oversized PNGs. Neither is hard to fix.

02 · High

The finding that matters most

H1 Deep link /#atelier does not scroll to the Atelier section High

Loading theonyxoffice.com/#atelier cold leaves the viewport at the very top of the page (scrollY = 0). Same for #practice, #selects, and #contact. Clicking the nav links after load works perfectly (About → scrollY 900, the Atelier offset), so the section IDs and in-app navigation are fine. It is specifically first-load navigation from a URL fragment that fails.

Why it matters: this is the exact URL in the request — the kind of link that gets shared, bookmarked, or dropped in a bio or DM. Every recipient lands on the hero and has to find the section themselves. A deep link that doesn't deep-link is a broken promise to the visitor.

Root cause (confirmed in the production bundle): a ScrollToTop effect runs window.scrollTo({top:0}) on route mount, and nothing reads location.hash to scroll to the target after hydration (scrollIntoView: 0, hashchange listeners: 0). The browser's native "scroll to #id" is overridden on load and never restored; Supabase's auth client also clears the hash during init.

Fix 
// after hydration, honor the fragment
useEffect(() => {
  const { hash } = window.location;
  if (!hash) return;
  const el = document.getElementById(hash.slice(1));
  if (el) requestAnimationFrame(() =>
    el.scrollIntoView({ behavior: "auto", block: "start" }));
}, []);
// and guard ScrollToTop: if (window.location.hash) return;

M1~49 MB of media on the pageMedium

Heaviest assets: spiral-crystal.mp4 12.4 MB, rice-cooker-scroll.mp4 5.3 MB, cp-02-communications.mp4 4.2 MB, plus two more ~3.5 MB clips. Range + immutable caching are in place, so this is a first-visit and metered-connection cost, not a repeat-visit one.

Fix
Re-encode the decorative loops (tighter H.264 CRF / lower bitrate, or AV1 · HEVC), cap dimensions to display size, and play-on-visible the below-the-fold clips. A silent background loop rarely needs more than 1–2 MB.
M2Content images are oversized PNGs where WebP belongsMedium

unicorn-card.png is 2.9 MB (1920×1433); dangote-preview, ia-sub-1, pierce-sub-1 all sit at 1.7–1.8 MB. Converting to WebP/AVIF and sizing to the display box typically cuts 70–85%.

The pipeline already emits WebP for the social share image, so this is a settings change, not new tooling. Adding srcset/sizes also stops phones downloading desktop-scale art.

04 · Accessibility

Where assistive tech struggles

M3Background videos ignore prefers-reduced-motionMedium

The site partly honors reduced-motion — it drops the Lenis smooth-scroll engine and lowers animation quality — but the autoplaying crystal video loops keep playing. axe flags no-autoplay-audio on 5 videos (muted, so the issue is the motion, not sound). Fix: pause or swap to a poster frame when reduce matches, alongside the existing downgrade.

M4Contact form fields have no programmatic labelsMedium

Name, email, and message carry only placeholder text — no <label>, aria-label, id, name, or autocomplete. Fails WCAG 1.3.1 / 4.1.2 and defeats autofill. The type/scope/budget toggles are buttons with no aria-pressed, so their selected state is invisible to a screen reader. Fix: add hidden labels + autocomplete, and give the toggles pressed state or radio semantics.

M5No <main>, <nav>, or <footer> landmarksMedium

axe: landmark-one-main (0 main landmarks) and region (55 nodes outside any landmark). A <header> exists, but content and the contact area aren't wrapped, so rotor/region navigation has nothing to jump to. Fix: wrap the body in <main>, label the nav, add a <footer>.

L4Keyboard focus ring is nearly invisible on primary navLow

Several ring/menu links compute a transparent outline (solid 2px rgba(0,0,0,0)), so a keyboard user can't see focus. Inconsistent — some buttons do get a visible ring. Fix: a real :focus-visible style on every interactive element.

L3 · L5Sparse alt text; mobile menu ignores EscapeLow

Only 3 of 16 content images have alt text (one truncated to "GOVERNMENT AFFAIRS AN"); describe the case-study visuals, keep alt="" for decorative layers only. Separately, the hamburger menu opens but Escape doesn't close it and focus isn't moved into or trapped in the panel.

05 · Security & SEO

Headers, metadata, and template leftovers

M6Missing hardening headers: CSP, X-Frame-Options, Permissions-PolicyMedium

Present and good: HSTS (1 yr + subdomains), X-Content-Type-Options: nosniff, Referrer-Policy. Missing: no Content-Security-Policy (no restriction on script/connect sources), no X-Frame-Options / frame-ancestors (clickjackable), no Permissions-Policy. Fix: add X-Frame-Options: DENY, a starter Permissions-Policy, and a report-only CSP allowing self + the fonts / storage / Supabase origins the app uses.

L6Contact form posts to Supabase with the public anon key — verify RLSOwner check

The form inserts into contact_enquiries using the anon key in the bundle. Normal for Supabase (anon keys are public), but safety rests entirely on Row-Level Security. Two owner actions: confirm the anon key allows INSERT but denies SELECT (or a public read would leak every submitted name/email/ message), and add a honeypot or rate-limit to this unauthenticated public insert. I did not probe the endpoint — verify it directly.

L1 · L2Lovable template leftovers & SEO gapsLow

Shipped to production in <head>: meta author=Lovable, twitter:site=@Lovable (so a social card credits @Lovable), and a literal <!-- TODO: Update og:title --> comment. Also no canonical, no og:url, no og:site_name, no JSON-LD, no sitemap.xml, and a bare title. Fix: own the meta tags, add canonical + Organization JSON-LD, and a title like "The Onyx Office — Digital Systems, Visual Direction & Emerging Intelligence".

06

What's already good — keep it

  • No console errors, no page exceptions, no failed requests on the real origin.
  • Clean transport: HTTPS, HSTS, nosniff, sane Referrer-Policy.
  • Smart caching: hashed assets immutable for a year; video supports HTTP Range (206).
  • Fast shell: TTFB ~0.2–0.7 s, 11 KB HTML, 179 KB gzip JS.
  • Stable layout: CLS 0, single H1, clean heading hierarchy.
  • Responsive: no horizontal overflow at 390 px or 1440 px.
  • Code splitting: the landing page loads only its own chunk.
  • Design craft: cohesive onyx/glass system; the spiral nav and scroll gallery are well tuned.
